## 主持循环

1. 玩家提交发言（沿用 say 或新增明确 language 行动，最终契约由后端尽早固化）。
2. 自然语言导演只读取该玩家能见的场景、NPC、公开可交互对象、合法动作及公开历史，返回受 schema 限制的结构化 Decision。
3. Decision 区分 dialogue / action / clarification / proposal。常规且明确的玩家动作本身即授权执行；歧义、条件句、多动作或 AI 主动建议的资源消耗/重大选择先澄清或待确认。不能替玩家选择立场。
4. Action 只能引用服务器允许的动作和目标 ID，经过身份、版本、回合、资源、可达性、剧情前置条件校验。模型不能决定 DC、骰子、伤害、给物品、任意写 flags 或宣布结局。
5. 规则执行与剧情触发在同一事务中更新权威状态，产生可见事件，再由模型依据已提交的事实叙述并提供下一步。无效模型输出或超时不允许部分扣资源/改剧情。
6. 自动触发有执行上限、固定顺序和一次性记录；无条件循环/重复触发/恢复后重放必须受控。

真实模型适配应新增 interpret/decide 能力，复用三家各自已核对的结构化输出协议；不只用本地正则取代真实 provider。Mock/本地导演需支持明确的中文行动、NPC回应与状态提示，界面始终诚实标识本地演示。真实模型尚无本项目凭证，因此通过注入 transport 的完整流程测试，不宣称已真实 API 联调。

## 剧情和规则数据

- 使用受限声明式条件与效果，不允许 eval、任意 JS 或任意工具代码。条件至少覆盖场景、行动/交互目标、旗标、物品、检定成败、敌人被击败；效果至少覆盖公共或个人揭示、设旗标、获得/消耗物品、开始/结束遭遇、解锁路径、目标进度、设置结局。
- 校验场景/NPC/物品/交互/旗标/触发器/结局引用、重复ID与互相矛盾的数据；导入失败给稳定错误码。
- 区分“玩家自由检定”和“剧本检定”。带剧情效果的 DC/消耗由服务端包数据提供，客户端/模型不能降低 DC 解锁剧情。
- 玩家可见投影包含当前场景的已公开交互对象、可到达路线、队伍背包、已公开任务、已揭示线索、游戏状态与结局；不返回隐藏目标名称、未解锁地点说明、完整触发器、旗标真相或他人秘密。公共模型上下文同样过滤。
- 触发条件与隐藏事实仅由可信剧情引擎读取；模型可以通过 public affordances 选择动作，成功后按引擎批准的事实叙述。
- 结局状态必须有完整收束与总结；结束后禁止继续改游戏状态，允许聊天/查看/导出。暂停/断线/恢复不触发额外剧情。

## 原创《雾灯地窖》完整新版本

至少三场景、可发现线索、铜铃物品、守卫遭遇、灯芯修复与点灯目标。至少一条和平通关路线、一条战斗通关路线和撤退/失败收束。

建议可操作旅程：调查入口 → 获取铜铃及提示 → 进入地窖 → 摇铃安抚守卫（或战斗击败）→ 解锁蓝灯室 → 修复灯芯 → 点亮蓝灯 → 完整结局。NPC交涉可提供线索或替代路线。检查失败应产生明确后果/可继续的替代选择，避免一次失败永久软锁；资源不足也应有有代价的恢复/绕行方式。不能因为玩家偏离预设就强制回到唯一解法。

本轮仍采用原创简化 d20；不扩大为完整 D&D 职业/法术/地图规则。自然语言需要覆盖示例和通用已注册动作，不承诺任意模组自动适配。

## 网页与 QQ

- 主要输入默认自然语言，仍保留手动规则操作。页面展示实际执行动作、检定/资源/剧情变化；明确区分发言、澄清、待确认提案与已执行结果。
- 提案确认/取消由当前玩家 token 验证，绑定版本和 ID；过期失效，不得多人代确认或重放。
- 展示背包、目标进度、已知交互和结局状态。帮助提示可以使用已知目标，但不得直接给出隐藏解法。
- QQ模拟发言复用同一个导演/规则/剧情入口；不能仍停留在纯模板叙述。真实QQ依旧不联调。
