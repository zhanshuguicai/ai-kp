# 第一半成品怎么验收

版本：0.3.0-half，2026-10-24。项目：`C:\Users\38365\CodexProjects\ai-kp`。

本轮交付的是“可配置模型和原文资料、可实际调用主持工具、可接 OneBot 的本地半成品”。没有真实 API/QQ 凭证，因此尚未验收真实模型的主持质量或真实群收发。离线演示是固定文案，不能用来判断 AI 是否会自由裁定和编写剧情。

## 先用 3–5 分钟验收软件流程

1. 双击项目里的 `start.cmd`，保持窗口开启。它会安装缺失依赖、编译并启动；已有依赖时不会重复安装。
2. 打开 `http://127.0.0.1:3000`。复制 `data/admin-token.txt` 的内容，填入“本机管理令牌”，点击“读取工作台”。若自己设置过 `AIKP_ADMIN_TOKEN`，使用该值。
3. 点击“一键加载内置示例 / 离线协议演示”，再点击“创建团并进入主持台”，然后“请主持人开场”。
4. 选“行动”，发送：“我不再犹豫，拆下门轴做成滑轮，和同伴把木箱吊到钟楼上。”应出现服务端骰点和公开记忆。该句没有预设动作注册，演示仅验证自由文本进入工具流程。
5. 切换第二名玩家，选“对话”发送一句话。固定演示不会为该类消息新增骰点。选“OOC”输入草稿后刷新，文字、玩家和消息类型应恢复。
6. 展开“QQ 桥接与本地事件模拟”，提交模拟消息。应显示公开回传和“未发群”标记；不应把主持私密笔记附在回传里。
7. 关闭服务后再次启动，读取原团。记录、骰点和记忆应保留。其他来源的新消息目前通过“刷新”读取。

真实 API 未配置时会明确报错，不会假装连接成功或静默换成演示。

## 再验收自己的资料与模型

1. 在“模型接入”填写厂商、Model、API Key 和必要的 Base URL，保存到服务器。推荐先试 `claude-opus-5-5`；日常成本候选 `claude-sonnet-5-5`，对照 `gpt-6.1-sol`。也支持 Gemini。
2. 点击“测试连接”。这会产生一次真实 API 请求；成功只证明本次工具协议连通，不代表主持质量通过。
3. 分别粘贴规则与剧本，或读取 UTF-8 TXT/Markdown 文件，保存后在开团处选择。无需转成剧情 JSON。每份最多200000字符，超限明确拒绝；PDF/OCR留待后续。
4. 新建一桌，选择真实模型与自己的两份资料，填写玩家名称/ID，然后请求开场。切换模型通过新建团完成，已开团保持原主 KP。
5. 连续提出普通对话、未预设行动、检定失败后的新办法、支线承诺回访，以及两名玩家的不同计划。重点看是否合理使用规则、真实骰点、记忆和剧情后果，是否保留玩家选择权。

完整同题评估见 `MODEL_DECISION_HALF.md`。目前没有本项目的真实模型对比结果，推荐是试验顺序。

## 接真实 QQ

使用自己已有且已登录的 OneBot v11 桥接器；本项目不自动安装或登录 QQ。

1. 桥接器开启 HTTP API（常见为 `http://127.0.0.1:5700`），在管理台填写地址及对应 Access Token。
2. 设置独立共享 Secret，在桥接器配置 HTTP POST 上报至 `http://127.0.0.1:3000/api/host/qq/events`。服务按原始请求体验证 HMAC-SHA1 签名。
3. 为当前团绑定群号，选择“仅 @ 机器人”或“群内所有消息”，再启用桥接。网页只是本机管理台，玩家在群里发言。
4. 群事件进入同一主持核心，发送使用 `send_group_msg`，只包含公开回复和骰点。管理台的“桥接器返回成功”或“异步接收”不等于已证明真实群送达，需要在群里核对。

接口说明见 `HOST_API.md`。当前只支持同机桥接；未实现公网部署或多进程运行。
