# KP 平台设计（v1）

目标：接入任意剧本，自动压缩上下文，根据剧本与 PL 行动调整节奏并作出反应的 AI KP 平台。
**不需要真人 KP，组织者也不会被剧透**：搭桌子的人和其他玩家一样，在游戏中第一次见到剧情。
新代码位于 `src/platform/`，旧版 `src/*.ts` 暂不改动，待新管线可用后再移除。

## 已定决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 主持者 | 没有真人 KP；组织者只搭桌子，不看秘密 | 组织者也能完整体验剧情 |
| 需要看秘密的工作 | 全部交给模型（剧本编译、泄密校验） | 取消"人工审核回复"的设计 |
| 主持结构 | 单个 KP 模型 + 规则版节奏导演 | 成本低、行为可预测；导演之后可换成 LLM |
| 规则层 | 可插拔适配，内置 7 个常见系统 | 模型决定"检不检定、检什么、多难"，规则层决定"怎么掷、算不算成功" |
| 事实来源 | 只追加的事件日志 | 摘要、记忆、状态都由日志派生，可重建 |
| 秘密 | 按数据字段隔离 + 输出校验 | 不只依赖提示词 |
| 工具错误 | 作为错误结果回传模型重试 | 不再因为参数错误让整轮失败 |
| 存储 | SQLite（`node:sqlite`） | 替代整体重写 JSON |

## 架构

```
渠道层   Web / QQ OneBot / …  → InboundMessage
回合管线 归一化 → 意图分类 → 剧本检索 → 上下文组装 → KP 工具循环 → 泄密校验 → 事务提交 → 发送
                                                         └→ 后台：上下文压缩、节奏评估
核心     剧本库 · 世界状态 · 上下文管理器 · 节奏导演 · 规则引擎
存储     事件日志 · 状态快照 · 摘要 · 剧本分块
模型     Anthropic / OpenAI / Gemini 统一工具协议
```

### 上下文分层

| 层 | 内容 | 更新 |
|---|---|---|
| L0 | KP 人设、规则说明（`rulesPrompt`）、工具说明 | 静态 |
| L1 | 核心真相 + 当前场景相关剧本分块、NPC 卡 | 每轮检索 |
| L2 | 世界状态快照 | 每轮渲染 |
| L3 | 章节摘要（公开版 / KP 版分开） | 超预算时滚动压缩 |
| L4 | 最近 N 轮原文 | 滑动窗口 |
| 导演 | 本轮节奏指令 | 每轮生成 |

压缩在回复发出后后台执行；摘要需对照世界状态校验（已发现线索不能丢）。

### 节奏导演信号

卡关（N 轮无新线索）、拖沓（场景超出轮数预算）、冷落（某 PL 久未发言）、紧张度、主线进度、收束条件
→ 输出 `hint / escalate / breathe / spotlight / wrap_up` 指令，KP 可不采纳但要记录理由。

## 规则层（已实现）

位置：`src/platform/rules/`，测试：`tests/platform/rules.test.ts`。

| id | 系统 | 核心机制 | 额外工具 |
|---|---|---|---|
| `coc7` | 克苏鲁的呼唤 7 版 | d100 骰低于技能；常规/困难/极难；奖励/惩罚骰；孤注一掷；技能基础值 | `sanity_check` |
| `dnd5e` | D&D 5e | d20+属性+熟练 vs DC；优势/劣势；豁免；攻击 20 暴击 / 1 失手 | |
| `pf2e` | 开拓者 2e | 四级成功度，±10 规则，天然 20/1 升降一级；熟练等级 | |
| `pbta` | 启示录引擎 | 2d6+属性：10+ / 7-9 / 6-；可选 3d6 取 2 | |
| `fate` | FATE Core | 4dF+技能 vs 阻力；平手/成功/风格成功；援引 +2 | |
| `storyteller-v20` | 黑暗世界 V20 | d10 骰池 vs 难度；1 抵消；大失败；专长；意志力 | |
| `generic-d20` | 通用 d20 | d20+调整 vs DC，天然 20/1 | |

所有系统共用：
- 工具 `check`（各系统参数不同）和 `roll`（任意骰子表达式：`NdM`、`d%`、`NdF`、`NdMkhK`）。
- 结果统一为 `CheckResult`：五级 `outcome`（大成功 / 成功 / 部分成功 / 失败 / 大失败），另带系统自己的成功度文字、一行公开 `summary`、建议的属性变化 `effects`（由状态层决定是否应用）。
- `valueSource` 标明数值来自角色卡、规则基础值，还是 KP 临时声明，方便审计。
- roll-over 系统要求**掷骰前给出 DC/阻力**，防止事后改难度。
- 技能名中英文与常见别名互通（角色卡写 "Spot Hidden"，KP 问 "侦查" 也能找到）。
- 工具 schema 兼容 OpenAI strict 模式（所有字段必填，可选项允许 null）。
- `executeRuleTool` 把规则错误作为 `{ ok: false, error }` 返回，交给 KP 层回传模型修正。

新增系统：实现 `RuleSystem` 接口并 `registerRuleSystem(...)` 即可。

## MVP（已实现）

启动：`npm run build` 后 `npm run platform`，打开 http://127.0.0.1:3100 ，填入 `data/admin-token.txt` 中的管理令牌。
数据存于 `data/platform.db`（SQLite）。不配置 API key 也能用 `demo` 离线演示模型试跑（固定脚本，无智能）。

| 模块 | 位置 | 说明 |
|---|---|---|
| 存储 | `storage/store.ts` | 事件日志（只追加）、回合、世界状态（带版本号）、摘要、剧本分块、角色卡、设置 |
| 剧本 | `scenario/chunker.ts`、`retriever.ts` | 按标题层级分块（Markdown、第X章、【】、一、），中文双字切词 + BM25 检索 |
| 模型 | `providers/` | OpenRouter Chat Completions（推荐）、Anthropic Messages、OpenAI Responses（无状态，回传加密推理）、Gemini generateContent；统一为 `step()` / `complete()` |
| KP | `kp/tools.ts`、`agent.ts`、`state.ts` | 规则工具（可暗骰）+ 剧情工具（场景/线索/NPC/剧情线/威胁时钟/紧张度/私密笔记/检索原文/回复与私聊） |
| 上下文 | `context/assembler.ts`、`compressor.ts` | L0–L4 分层预算；超预算时后台生成片段摘要，片段多了再合并成章节 |
| 导演 | `director/director.ts` | 卡关、连续失败、时钟将满、场景过长、冷落玩家、主线结束 → 节奏建议 |
| 管线 | `engine.ts` | 同团串行；messageId 去重；一轮的变更在一个事务里提交；失败只保留已掷骰点 |
| 接口 | `server.ts` | `/api/v1`，仅本机，管理令牌；网页在 `web/platform/` |

工具循环的容错：参数错误、未知工具、JSON 损坏都作为错误结果回给模型重试（超过 6 次才失败）；模型只输出文本时直接当作回复；只有输出被截断、拒绝或 8 步内没有回复才判定本轮失败。

### 模型选择（OpenRouter）

- 默认主力：`anthropic/claude-opus-5.5`，推理强度 medium，输出上限 8000（推理 token 也计入上限）。
- 默认辅助（摘要）：OpenRouter 用 `anthropic/claude-haiku-5.5`，直连 Anthropic 用 `claude-haiku-5-5`；其他供应商沿用主力模型。
- 每个团可以单独设置主力模型、辅助模型的供应商和型号（`PUT /api/v1/campaigns/:id/models`，网页右侧"模型与用量"）。留空即用默认。
- 工具调用时，模型返回的 `reasoning_details` 原样放回发起调用的 assistant 消息，保证 Claude/Gemini 多步推理连贯。
- 提示缓存：上下文分成"稳定段"（人设、规则、KP 概要）和"变化段"（本轮原文、状态、摘要、近期记录、节奏建议）。Claude 两段各加一个缓存断点；Gemini/OpenAI 依靠前缀自动缓存。
- 每轮记录输入/输出/缓存命中 token 和费用（OpenRouter 返回 `usage.cost`），网页显示全团累计。摘要调用的用量暂未统计。

已知限制：
- API key 以明文存在本机 SQLite 中，按敏感文件对待。
- 泄密只靠数据隔离和提示词，还没有对公开回复做校验（路线第 3 步）。
- 尚未用真实 API 联调；三家适配只经过请求/响应格式测试。
- 意图分类交给主 KP 判断（kind=auto），没有单独的小模型。

## 角色与防剧透（已实现）

| 角色 | 入口 | 能看到 |
|---|---|---|
| 组织者 | `/`，管理令牌 | 团配置、玩家与邀请、模型与费用、不含剧情的诊断（工具名、成败、节奏建议的类型、token）、公开记录 |
| 玩家 | `/play#t=邀请令牌` | 公开记录、发给自己的私聊、公开状态与玩家版摘要、自己的角色卡 |
| KP 视图 | `GET /api/v1/campaigns/:id/kp` | 全部内容；**必须先解锁**（`POST .../reveal {confirm:true}`），不可撤销，并会公开通知全桌 |

- 剧本导入只上传文件，页面不显示原文。
- 邀请令牌只在生成时显示一次，数据库只存哈希；重新生成后旧链接失效。令牌放在网址 `#` 后面，不会出现在服务器日志里，页面加载后立即从地址栏清除。
- 组织者接口不返回：KP 笔记、威胁时钟、暗骰、私聊、KP 版摘要、节奏建议原文、剧本原文；"立即压缩"只返回是否生成了摘要。测试会在一个包含所有类型秘密的团里检查这些视图。
- 边界：组织者掌握服务器和数据库，技术上总能看到秘密；平台保证的是"不会意外看到"。
