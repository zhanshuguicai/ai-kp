# 浏览器与启动验收

2026-10-24，在本机 IAB 浏览器与独立 `data/preview/` 演示目录验收。仅使用 Mock KP 和原创样例，无真实模型请求、无真实 QQ 消息。

## 已实测

- 健康接口返回 ok，首页 HTTP 200。
- 实际通过 Windows `start.cmd` 启动入口完成构建并监听本机端口，随后健康接口再次返回 ok。
- 管理身份创建房间、邀请码加入角色；房主和玩家身份可同时保留。
- 个人札记显示在玩家视图，房主默认视图不显示主持秘密。
- 相邻场景移动，公共事件、当前地点和在场 NPC 更新。
- 自由叙述产生玩家发言与 Mock 主持回应，不自动改规则数值。
- 检定产生真实后台骰点并扣体力。
- 开始演示战斗、攻击、敌人反击、结束回合与界面同步。
- 导出 JSON 存档，检查不含 identities、inviteCode、qq、receipts 等身份与去重数据。
- 从导出文件恢复为新房间，认领轮换身份后的原角色，再次检定成功提交。
- QQ 本地身份绑定与消息模拟进入同一权威事件流；未连接真实 QQ。
- 关闭并重新启动后台后，浏览器重载仍保持房间版本 12、角色身份、个人札记、场景及敌方生命值。
- 最后一次重载未观察到浏览器 error/warn 日志。
- 检查桌面三栏布局和约 390px 窄屏；窄屏 DOM 内容宽度与可视宽度相同，未出现横向溢出。视口覆盖已恢复默认。

## 已修正并复验

首次浏览器检查发现：右侧快捷移动会把中央输入类型持续改为 move，之后输入的对话可能被当作移动处理。

前端执行者进行一次同档定向修复：快捷移动独立提交，不改变中央类型；非对话操作禁用文字框并保留草稿；只有对话成功才清空草稿。浏览器复验观察到快捷移动后类型仍为 say、草稿保留，随后检定与对话分别正确提交。
